# 04 — Chat UI (Streamlit) & CLI harness

Status: DRAFT (brainstorm 2026-08-15).

## Principles
- The agent core is UI-agnostic: `agent.answer(message, session_state) -> Answer` (streams Plan first). Streamlit
  and the CLI harness share 100% of the logic.
- Render the fixed synthesis structure (03) faithfully; the UI never re-interprets numbers.
- Transparency is a feature: show the Plan before the answer, and the tool trace on demand.

## Layout — single page `src/airport_agent/ui/streamlit_app.py`
**Sidebar**
- **Conversations:** list of chats (new / switch / rename / delete). Each chat has its own `SessionState`; all
  chats persisted to `data/sessions/<id>.json` (history, state) so they survive reload/restart.
- Provider status: configured provider(s) and startup health check result (Gemini only for now).
- Data vintages per source (from `DataService.source_vintages()`), with staleness hint.
- Defaults the user may override for this chat: horizon, scoring preset, peer group (hub class / region / all).
- Four sample questions as one-click starters. Link to `docs/DESIGN.md`.

**Main column** — chat history + input. Each assistant turn renders:
1. Plan line (caption; streamed as soon as the Plan is produced, before execution)
2. Headline
3. Evidence table (`st.dataframe`; column tooltips from `MetricSpec`); "more metrics" expander for hidden rows/cols,
   with the Concierge's one-line reason for what it hid
4. Analyst view + agreement/disagreement callout
5. Assumptions & uncertainty expander (open by default on analytical answers)
6. Follow-up chips that pre-fill the input
7. "Show work" expander: tool trace (tool, args, rows returned, provider used, latency, hint truncation flags)

**Errors:** `st.error` with the provider-chain message (03 failure policy). No partial answers.

## State
`SessionState` per conversation in `st.session_state` + JSON persistence. No cross-request caching of LLM
outputs or reports; follow-ups use `SessionState.last_reports` (conversation memory, not a cache).

## CLI harness — `python -m airport_agent.ui.cli "question" [--session id] [--json]`
Non-interactive entry for tests and dev subagents; prints the Answer as text or JSON. Not a user deliverable.

## Voice — separate branch `feature/voice`, one agent, timeboxed
`st.audio_input` → speech-to-text via the primary provider (Gemini free tier accepts audio) → normal text pipeline
→ optional TTS of the headline (`gTTS`). Merged only if clean; otherwise documented as attempted.

## Nice-to-have (only if time remains)
Small trend sparkline (enplanements 10y) inside airport profile answers.

## Out of scope
Auth, multi-user, hosting, charts beyond tables/sparkline, mobile layout.

## Testing
- Core: covered by agent tests. UI: a smoke test that boots the app with `FakeDataService` and a fake LLM and
  renders one answer of each type (informational, rank, compare, diagnose, error).
- Session persistence round-trip test.
