# Known Limitations & Key Tradeoffs (living log)

Each entry: **What** · **Type** (Constraint = imposed by data/time; Decision = our choice) · **Impact** · **Mitigation** · **Status**.
This log feeds the "Key tradeoffs" section of the final DESIGN.md.

| # | What | Type | Impact | Mitigation | Status |
|---|---|---|---|---|---|
| 1 | OTP raw detail (taxi-out, per-flight distance groups) only for trailing 24 months; ~270MB/month makes 10y raw infeasible in a day | Constraint | Delay *detail* trends limited to 2y | BTS Delay Cause dataset (airport-month, 2003→) for 10y delay trend | Accepted |
| 2 | T-100 International Segment table code not yet verified | To verify | Route-level intl detail may be missing | Socrata intl inbound/outbound totals (verified) as fallback | Resolved: not landed. 15-min probe (2026-08-16) of FIL/FIH/FIS/FIT/FIN/FIQ/FIP/FIO/FIC/FIB/FID/FGH/FGJ-FGQ/FMG all 302 to /Homepage.asp (invalid gnoyr_VQ); TranStats database-index pages did not surface the code either. `routes_month` is domestic-only (`is_international=False` for every row); Socrata's `intl_out_passengers`/`intl_in_passengers` airport-level totals remain the only international signal. Accepted |
| 3 | FAA ASPM/OPSNET (official capacity/throughput) login-walled and unreachable | Constraint | No official hourly capacity vs demand; congestion inferred from delays, taxi-out, load factor, upgauging | Curated slot-level/runway facts; state as inference | Accepted |
| 4 | Pre-2014 per-airport monthly totals not in Socrata | Constraint (soft) | 10y horizon = 2016→2026 fine; deeper only via TAF annual actuals | TAF actuals 1976→ for enplanements/ops | Accepted |
| 5 | Terminal/gate counts not in any free dataset | Constraint | Cannot compute gates-per-Mpax directly | Curated YAML for ~30 major airports; note absence elsewhere | Accepted |
| 6 | Future airline schedules (OAG/Cirium) paid | Constraint | No forward capacity supply signal | FAA TAF forecast as demand-side substitute | Accepted |
| 7 | Airport financials (FAA CATS Form 127) | Resolved | Queryable per year/hub class; CPE on line 16.5 | Caveat: self-reported, unaudited, non-uniform basis — surface in answers | Resolved |
| 8 | Causal "why" (runway geometry, ATC rules) not structured | Constraint | Explanations need text | Curated, sourced airport_facts.yaml; LLM must cite it or say unknown | Accepted |
| 9 | Free-tier LLM limits (~10 RPM Gemini) | Constraint | Tool loops must be short; bursts hit 429 | ≤6 calls/answer, follow-ups reuse session memory; **no silent fallback — fail loudly with actionable message** | Accepted |
| 16 | Single LLM provider (Gemini free tier) for now; Groq/NIM fallbacks deferred | Decision | 429/outage ⇒ loud error rather than fail-over | LiteLLM router keeps the door open via `providers.yaml`; revisit at the end if time remains | Accepted |
| 10 | Snapshot committed in repo (≤100MB) rather than fetched at first run | Decision | Reviewer runs offline instantly; data ages | `refresh` command + `--check` staleness; vintages shown in answers | Accepted |
| 11 | In-process tools rather than MCP as primary transport | Decision | Simpler, provider-agnostic | Optional FastMCP wrapper over same registry | Accepted |
| 12 | One Concierge + structured dispatch to code (Deterministic Analyst) and LLM specialists, rather than free conversational multi-agent handoffs | Decision | Low variance, bounded LLM calls | Structured `AnalysisRequest` with ≤200-char hint (600 for general_analyst) | Accepted |
| 13 | Gemini key shipped in `.env` inside zip (throwaway account), not hosted | Decision | Zero-setup for reviewer; key revoked after review | `.env` gitignored; commit-guard hook; clear error if key missing/invalid | Accepted |
| 14 | O&D vs connecting share needs BTS DB1B/OD-40 (large quarterly files) | To verify | Central to Moody's/Fitch; without it P3 lacks the strongest market-quality signal | Timeboxed adapter attempt (1 recent year); else drop `od_share` and log | Open |
| 15 | No silent LLM degradation | Decision | If all providers fail, no answer is produced | Loud, actionable error message; provider chain is the resilience | Accepted |
| 17 | `contracts/registry.py` reads `config/metrics.yaml` from disk — the one sanctioned I/O inside `contracts/` | Decision | Breaks the "contracts are pure types" rule in a single, narrow place; registry becomes loadable without a data layer | Read-only, no network, path injectable (`load_registry(path)`); every other module in `contracts/` stays pure types + Protocols | Accepted |
| 18 | Specialist hint capped at 200 chars (600 for `general_analyst`) | Decision | Concierge cannot smuggle analysis into free text; long user nuance may be truncated | Structured `AnalysisRequest` fields carry the substance; hint is steering only, validated in contracts | Accepted |
| 19 | Five tier-C metrics (`asv_utilization`, `terminal_sqft_per_nbeg`, `dscr`, `days_cash`, `use_agreement_type`) have no public source | Constraint | P2/P5 lack capacity-utilization and debt-coverage depth | Kept in the registry as documented gaps, tier C is never scored and never invented; surfaced as "not available" in answers | Accepted |
| 20 | `contracts/` + `config/metrics.yaml` frozen at tag `contracts-v1` | Decision | Downstream workstreams build against a stable ABI; late modelling mistakes are expensive to fix | Change requires a human decision, `CONTRACTS_UNFROZEN=1`, and a rebase of every open worktree | Accepted |
| 21 | `FeatureMatrix` horizon rule: no relabeling across horizons | Decision | A metric that does not declare the requested horizon returns None, so matrices at 5y/10y are sparser than at 12m | Rule stated in the `DataService.get_feature_matrix` docstring and enforced by the shared contract suite; scorer must handle None (coverage reported per answer) | Accepted |
| 22 | OurAirports ICAO resolution falls back `icao_code` → `ident` → `gps_code` | Constraint | A minority of rows lack `icao_code`; the fallback fields can disagree with the true ICAO id | Fallback chain documented in the adapter; identity fields are display-only, joins use IATA/LocID | Accepted |
| 23 | `hub_size` / `faa_region` / `commercial` are placeholders at OurAirports ingest until TAF/Socrata overwrite them | Constraint | Airports absent from TAF/Socrata keep placeholder identity values | Overwrite order fixed in the snapshot build; `commercial=True` requires presence in Socrata or TAF with enplanements > 0 | Accepted |
| 24 | Row vintage = newest raw-file mtime, not the source's own publication date (mtime-as-vintage proxy) | Decision | A cached download re-used months later carries its file date; vintages can understate data age | `file_vintage` derives from the raw files themselves (never "now"); refresh `--check` reports staleness per source cadence | Accepted |
| 25 | `coverage` appears on analysis-tool results only (mean `ScoreRow.coverage`), not on plain data-tool results | Decision | The LLM cannot cite a coverage figure for raw lookups | Design 03 amended; data tools still carry provenance + truncated | Accepted |
| 26 | `low_confidence` flag ignores pillars that are absent by design for the preset | Decision | An answer scored on fewer pillars is not flagged low-confidence merely for the absence | The caveat text instead states the forgone weight explicitly ("P4/P5 excluded by preset: N% of weight") | Accepted |
| 27 | `PRESET_NAMES` in the agent planner duplicates the preset list in `config/scoring_presets.yaml` (second source of truth) | Constraint | Adding a preset requires touching both places or the planner rejects it | Noted here + covered by a golden test that runs each preset name end-to-end | Accepted |
| 28 | OTP ingested for trailing 12 months only (RESCOPE 2026-08-16, supersedes plan 2a's 36 months) | Decision | `pct_arr_delay_gt15`/`avg_dep_delay_min` 3y/5y horizons are None; only 12m is honest | `otp_months: 12` in `config/sources.yaml`; ~12 months x ~30MB zip instead of ~1.1GB | Accepted |
| 29 | census_cbsa: population + Gazetteer centroids only, no BEA (RESCOPE 2026-08-16, part of Core-6) | Decision | `msa_gdp_per_capita`/`msa_gdp_cagr_5y` are None; `catchment.gdp_real_usd` always None | `cbsa_population`/`cbsa_pop_cagr_5y` still computable; presets renormalize over P1-P3 + `npias_dev_per_enpl` | Accepted |
| 30 | Scoring percentiles are computed against the whole airport universe (all airports the DataService lists, ≤600) partitioned by peer group, not only the airports in the question | Decision | A regional question still ranks each airport against its national hub-class peers; ranking a lone large hub among small hubs is meaningful | Stated in every report's caveats ("Percentiles computed within … across N airports"); FeatureMatrix fetch is one call | Accepted |
| 31 | Long-haul passenger share weights departures on rows with seats>0; freight share weights freight lb (RouteRow has no per-row pax/cargo departure split) | Decision | Mixed pax/cargo routes count fully as passenger departures | Convention flag on the Metric; freight variant answers cargo questions (ANC) | Accepted |
| 32 | Unmet-demand "signals" are quartile heuristics (pct ≥ 0.75 within hub class) over the diagnose bundle | Decision | Indicative, not causal; thresholds are stated | Explanation lists every signal ✔/✘ with values; caveat says "indicate, not prove" | Accepted |
| 33 | `Plan.filters` carries the AnalysisRequest fields and per-tool `tool_calls[{tool, args_json}]` (arguments as a JSON string) so the Plan is one portable structured-output call with no free-form nested objects | Decision | Slightly clunkier schema; args are parsed by code | Args are still pydantic-validated by the ToolRegistry; bad JSON becomes a tool error in the trace, never a silent empty call | Accepted |
| 34 | Specialist evidence is resolved by code from tool results and deterministic evidence via `evidence_refs[{iata, metric_id}]`; unresolved refs are dropped and listed in caveats | Decision | The specialist cannot introduce a number; a lazy specialist cites less than it could | Prompt requires the refs; report evidence falls back to metric-id matching, and an ambiguous match is flagged in the caveats | Accepted |
| 35 | Synthesis JSON parse failure falls back to the deterministic explanation as the headline, with the uncertainty note "synthesis text unavailable - showing raw report" | Decision | Rare, and visible to the user when it happens | Formatting degrades, reasoning does not: tables, citations and assumptions are unchanged; provider failures still raise LLMError loudly | Accepted |
| 36 | Specialist system prompts run about 2-3k tokens because the metric slice carries full definitions, formulas, tiers, sources and caveats | Decision | More prompt tokens per specialist call than a summary slice would need (expansion/general carry all five pillars) | Accepted deliberately: the full slice is what stops the model inventing metric ids or definitions. A `metric_detail: summary` front-matter option is the fallback if the prompt budget ever bites | Accepted |
| 37 | `PLAN_SCHEMA`, `SPECIALIST_SCHEMA` and `SYNTHESIS_SCHEMA` are portable JSON-schema subsets (type/properties/required/items/enum/description only, no anyOf, oneOf, $ref, additionalProperties or nullable), using "none" / [] / "" as the unset sentinels | Decision | No optional or union-typed fields; every key is required and unset values are sentinels the code maps back to None | Works unchanged across Gemini and any other structured-output provider added later via providers.yaml; a schema test asserts the forbidden keywords never appear | Accepted |
